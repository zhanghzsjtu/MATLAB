三、缺陷与偏差明细（按优先级）

#级别位置问题状态
1 P2 逻辑 gptp_bmca.v 原 129 行 stepsRemoved 比较恒真：if (i_rem_steps_removed < i_rem_steps_removed + 1) 永远为真，导致 ROLE_PASSIVE 永远不可达、语义错误（本意是比较本/对端 steps）。 仿真盲区：现有 tb 只测 "对端优→Slave" 与 "对端差→Master"，两种恰好碰巧正确，未暴露。 已修复
2 文档 README.md §2 精度表 精度夸大：称 "1ns LSB"，实际 125MHz 时钟下整数 ns 为 8ns 步长， sub-ns 仅由 DDS 频偏累加器平均体现（长期频率精度，非每拍 1ns 绝对分辨率）。 已修正
3 文档 README.md §3 gptp_top 接口不符：文档称 top 输出 ro_rx_ts_ns/frac、ro_tx_ts_ns/frac， 但 gptp_top.v 实际未向顶层暴露（仅内部 residence 外送）。 已标注
4 集成隐患 gptp_switch.v 131–134 行 TX 边沿复用 RX：.i_tx_sof(w_rx_sof[p])、.i_tx_eof(w_rx_eof[p])、 .i_pkt_vld(w_is_event[p])。收帧同时被当作发帧，HTSU 的 residence 在 switch 下 永远算不出（无独立 TX 流驱动 WAIT→TX）。当前仅 Pdelay 独立工作故 tb 仍 PASS， 但 "共享时间基准 + 真实转发时间戳" 未闭环。属文档已声明 TODO 的简化未完成。 待办
5 架构隐患 gptp_switch.v 76–87 / 120 行 多端口 servo 争夺共享 PHC：u_phc 仅接端口 0 的 servo（w_adjfine_wr[0] 等）， 其余端口 servo 的 adjtime/adjfine 在 gptp_top 内被硬接 1'b0 屏蔽。 即多端口各自 servo 会"打架"，只有端口 0 生效；GM 端口选择逻辑缺失（文档未说明）。 待办
6 次要 gptp_tc.v 35 / 77 行 o_cf_rd 在 one-step 模式下随 i_pkt_vld 恒拉高，语义混乱 （two-step 才需 rd original CF）；且作为输出端口无任何消费者。 待办
7 次要 gptp_mac_glue.v TX 路径 TX 直接 o_tx_data <= i_rx_data 回环，CF 字节级改写完全未做 （仅置 ro_cf_wr_done 标志）。文档 §6 已声明 TODO，属已知限制。 已知

四、修复内容（本次已落地）

  • BMCA 恒真 bug 修复（gptp_bmca.v）：删除恒真条件， "对端优 → Slave" 语义明确；保留 ROLE_PASSIVE 编码并注释说明待扩展本地 stepsRemoved 后启用。重编译复跑 9/9 仍 PASS，行为正确。
  • README §2 精度表：将 "1ns LSB" 改为 "8ns 步长 + sub-ns 平均频率分辨率"， 并新增精度说明段，明确指出 1ns 绝对分辨率需提频或相位插值（TODO）。
  • README §3 gptp_top / gptp_bmca：如实标注 top 未暴露 t2/t3 时间戳、 BMCA Passive 修复说明与测试盲区提示。

五、建议的后续工作（按优先级）

  • [高] 为 BMCA 补一个能触发 ROLE_PASSIVE 的 tb 用例 （需先引入 i_local_steps_removed 输入端口，按 802.1AS 标准比较 本/对端 steps 决定 Slave/Passive），消除测试盲区。
  • [高] 在 gptp_switch 中引入真实的 TX 转发流（或独立 i_tx_sof/eof 驱动），让 HTSU 的 residence 在多端口下真正可算，闭合 "共享时间基准 + 转发时间戳"。
  • [中] 设计 GM 端口仲裁：多端口 servo 不能同时写共享 PHC， 应由 BMCA 选出的 GM 端口（或固定端口 0）独占 adjtime/adjfine，其余端口 servo 输出 gate 掉。
  • [中] 清理 gptp_tc 的 o_cf_rd 语义（one-step 下移除或置 0）。
  • [低] gptp_mac_glue 完成 CF 字节级改写（接 FIFO + 字节计数器定位 CF 偏移）。
